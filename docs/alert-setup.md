# Local alert setup and safe test sends

1. Open `https://127.0.0.1:4200/subscriptions` after starting the app. A new local profile has all 24 approved event-type tags selected. Click a tag to remove or restore it; **Save event types** persists the selection, even when none are selected. Existing legacy per-type subscriptions keep their old destinations/paused state and are available under **Advanced**; saving shared types does not silently unpause them.
2. Sign in at `/admin/login` to configure channels. For **email**, obtain your provider's SMTP hostname, username and app password separately; being logged in to webmail does not authorize SMTP. Enter From and **Send alerts to** as readable email addresses, STARTTLS port 587, and save. The SMTP password remains masked, protected on disk, and is not shown again. No automatic email can reach a recipient until a valid recipient and SMTP service are saved. A separate explicit email test sends once to the chosen test address.
3. For **Slack**, create/install a Slack incoming-webhook integration in your workspace and select the channel there. Being signed in to Slack does not give this app a webhook. Enter a readable channel label and paste the incoming-webhook URL **only** into the masked Slack settings field. Save to start automatic delivery; the admin-only separate test requires your explicit confirmation. Never paste a webhook URL into a channel label or chat.
4. For another service, use **Additional channel · HTTPS webhook**: enter its readable channel ID and label, public HTTPS webhook URL, POST or PUT method, a valid JSON template (`{{title}}` / `{{body}}` in JSON string values), and optionally an `Authorization` header value. Save once, without changing app code. The URL/authorization are stored with the app's protected keys and redacted from status. Outbound private/local IPs, untrusted DNS answers and redirects are refused. An admin-only one-shot test is available for each saved enabled webhook. Platforms requiring OAuth or interactive payload formats may require a separate adapter; do not assume arbitrary webhooks accept the template.
5. Return to the feed. It refreshes automatically while visible; the small **Debug** checkbox reveals provenance/score diagnostics and **Send TEST event**. Any local viewer may trigger this bounded action. It creates a clearly labelled synthetic `world-news` item, follows the saved `world-news` choice, and queues one notification for each matching configured channel. A global cooldown/daily limit protects destinations; a test is not an activation prerequisite. Scores are rule-based metadata strength, **not** an approved uniform `> 0.70` cutoff.

Keep app data, protected settings and encryption-key volumes together across relaunches. Do not share SMTP passwords, Slack URLs, or generic webhook tokens in chat or screenshots. SMTP server acceptance is not proof of inbox arrival; verify the selected inbox and Slack channel manually. Global provider coverage and native Windows recovery remain separate verification limits.
