# Task 24 admin wall: implementation evidence (pending integration)

`src/api/Admin/` supplies local PBKDF2-SHA256 password verification, a hardened session cookie, CSRF-protected login and logout, authenticated `/admin` HTML and `/api/admin/status`. The Angular root now routes `/admin` to `src/web/admin/admin.component.ts`, preserving the existing backend-health shell. Bootstrap 5.3 CSS is bundled locally; the responsive admin screen has a password form, source/poll table, queue/failure status and logout. An unauthenticated API response shows login; a missing/unreachable API shows an honest unavailable state, not healthy/empty data. The server-rendered `/admin` fallback remains usable on the API host. No default password or hash is committed. Set `WorldAlerts__Admin__PasswordHash` in the process environment, using a freshly generated `AdminPassword.Hash(password)` value. If unset or malformed, login fails closed. Serve the application through HTTPS for the Secure cookie and CSRF cookie; do not expose admin login over untrusted plaintext HTTP.

**Parent integration:** in `Program.cs`, add `using WorldAlerts.Api.Admin;`, call `builder.Services.AddAdminWall()` before `builder.Build()`, and `app.MapAdminWall()` after build; ASP.NET Core minimal-host authentication/authorization middleware is auto-registered when these services are present (or call `app.UseAuthentication(); app.UseAuthorization();` explicitly before routes). Register an `IAdminOperationsReader` implementation in DI for actual runtime values **before or after** AddAdminWall: default is registered using `TryAddSingleton`. `ReadAsync(CancellationToken)` returns `AdminOperationsSnapshot(Sources, Delivery)` where each source has `SourceId`, `Health`, `PollStatus`, `LastPollUtc`; delivery has `Status`, nullable `Queued` and nullable `Failed`. The default returns explicitly **unavailable**, never a fake healthy/empty queue. Implement the reader from live source-poll state and persistent delivery queue and count terminal failed sends, not an ephemeral in-memory list. Contract values must contain no secrets, destinations, message payloads, provider URLs or exception messages. The API and HTML encode/present only this restricted projection. The Angular root imports `AdminComponent` via `src/web/src/app/app.routes.ts`.

**Frontend launch for local review:** from `src/web/`, run `npm start -- --host 127.0.0.1 --port 4200 --ssl`, then open `https://127.0.0.1:4200/admin` and accept the local development certificate warning. Its same-origin proxy sends `/api`, `/admin/login` (GET/POST), and `/admin/logout` (POST) to `https://localhost:7021`. `secure: false` applies **only** to proxy verification of the locally trusted development certificate, not session-cookie security; both browser and upstream connections use HTTPS. Backend direct `/admin` continues to serve protected HTML; production serving of the Angular build on `/admin` needs a separate composition-root/static-host decision, not implemented by this frontend worker. Do not use plain-HTTP frontend when exercising secure session/CSRF cookies.

**Checks:** `npm test -- --watch=false` passed 9 Angular tests (including route, unauthorized/unavailable states, CSRF login/logout flow and rendered projection); `npm run build` produced `src/web/dist/web`. The dev server returned HTTP 200 for HTTPS `/admin`. Before the backend was relaunched, `/api/admin/status` returned **404** on the previous port 5001; that is historical evidence, not a current claim about the new HTTPS backend. `AdminWallTests` now creates HTTPS fixture clients; final C# test execution belongs to the parent, who serializes builds. No external provider or real sends were used.
