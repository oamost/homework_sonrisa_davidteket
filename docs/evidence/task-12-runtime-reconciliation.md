# Task 12 collection-state reconciliation (agent evidence; pending human verification)

The existing `CollectionStateStore` exposes `TryInitialize`, `RecordSuccess`, `RecordFailure`, `TryGet` and `ListAll` over the `SourcePollState` SQLite table. The ingestion workers and admin adapter had already been changed to call `Initialize`, `PollAsync` and `SnapshotAsync` over a different table, `SourcePollProgress`, producing compile errors. The reconciliation retains the existing persisted-state API and health classification (stale after 20 minutes; failed after three consecutive failures) while adding compatible runtime methods and copying earlier `SourcePollProgress` rows into the canonical `SourcePollState` table with `INSERT OR IGNORE` on initialization. The old table is left intact; existing canonical rows are not overwritten. Any concurrent older API process still writing the old table must be stopped by the operator before using the reconciled runtime; this worker did not stop existing processes.

Polling now calls the existing `SourcePollGuard` to prevent same-source overlap, uses `PollCadence` against persisted last-attempt and next-due times, records exception **types** rather than exception messages, and continues to other configured sources on failures. Each source can optionally specify `PollMinutes` to slow collection relative to its family interval; overrides cannot speed it up. `Program.cs` uses best-effort collection/queue initialization to preserve the existing unhealthy-database health behavior. A task-12 test that originally created a *different* parent path from its blocker file was corrected to put the database under that blocker.
